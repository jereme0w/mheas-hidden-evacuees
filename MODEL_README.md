# Model documentation

This repository contains two distinct model pathways corresponding to the accompanying paper: an explicit household report-priority model and a learned regional visibility model. All supplied training data, scenario context, reports, and evaluation material are fictional.

## 1. Household report-priority model

The implementation is in `backend/contextual_prioritisation_model.py` and follows Table 3 and Eqs. (1)–(2) of the paper.

### Normalisation and weights

| Factor | Normalisation | Weight |
|---|---|---:|
| People affected (P) | 1, 2, 3, 4+ → 2.5, 5, 7.5, 10 | 0.095 |
| Immediate danger (D) | No, Yes → 0, 10 | 0.285 |
| Self-reported urgency (U) | 0–2, 3–5, 6–8, 9–10 → 1, 2, 3, 4 | 0.050 |
| Vulnerability (V) | None, 1, 2, 3+ factors → 0, 5, 7, 9 | 0.190 |
| High-risk vulnerability | Injury, medication dependency, or limited mobility raises V to at least 8 | — |
| Need | Communication/electricity 4; transport/other 5; food/sanitation 6; water/shelter 8; medical 9; rescue/evacuation 10 | — |
| Shelter condition | Safe, Unsure, Unsafe → 0, 5, 8 | — |
| Need severity (N) | Maximum of reported-need and shelter values | 0.1425 |
| Responder access (A) | Yes, Unsure, No → 0, 5, 10 | 0.1425 |
| Hazard intensity (Q) | Light, Moderate, Strong, Severe → 2.5, 5, 7.5, 10 | 0.040 |
| Infrastructure disruption (I) | Normal, Minor, Moderate, Major, Severe → 0, 2.5, 5, 7.5, 10 | 0.035 |
| Communications disruption (C) | Normal, Intermittent, Outage, Major Outage → 0, 5, 7.5, 10 as specified in the paper's mapping | 0.020 |

The weighted score is mapped to Low (<3), Moderate (3–<7), High (7–<9), and Critical (>=9). The maximum attainable score is 9.51. High and Critical require immediate danger under the current mappings, Critical additionally requires responder access = No, and a one-person household can reach at most 8.80.

The 65 fictional Riverford reports yield 28 Low, 20 Moderate, 7 High, and 10 Critical classifications. These expected categories are generated by the same published rules, so matching them is an implementation-consistency check rather than independent validation.

## 2. Regional visibility model

The implementation is in `backend/regional_model.py`. It estimates the number of distinct reporting households expected under functioning reporting conditions and compares this with the observed number.

The fitted reporting-rate function stored in `models/regional_model.json` is:

```text
p_hat_r = exp[-6.8295
              + 0.4097(M_r - 5)
              + 0.9635 K_r
              + 0.5451 ln(T_r + 0.1)
              + 1.3010 R_r]
```

Expected reports are `E_r = H_r × p_hat_r`. The shortfall is `G_r = max(E_r - O_r, 0)`. Communications status is retained as context but is not an input to the expected-rate function.

The predictive distribution is negative binomial with overdispersion `0.08`, matching the value used in the paper’s scenario calculations. For a city snapshot containing `n` districts, the silence threshold is `0.05/n`; an unusually low count also requires `E_r >= 5`. Substantial damage is `K_r >= 0.6`. The resulting categories are Investigate (both conditions), Monitor (either condition), or No alert (neither condition).

### Riverford demonstration

| District | Observed | Expected | Assessment |
|---|---:|---:|---|
| Central | 36 | 43.82 | No alert |
| Eastbank | 18 | 40.83 | Monitor |
| Westbridge | 0 | 67.57 | Investigate |
| Hillcrest | 4 | 8.30 | No alert |
| Industrial | 0 | 0.43 | No alert |
| South Meadows | 7 | 2.60 | No alert |

Westbridge is investigated because its zero observed reports are extremely unlikely relative to its expected reporting level and its assessed damage exceeds 0.6. Industrial also has zero reports, but its expected count is only 0.43, so zero reports are not treated as anomalous.

## 3. Synthetic fitting and held-out checks

`datasets/training_reports.csv` contains 2,880 synthetic region snapshots generated from 120 fictional earthquake scenarios. Whole earthquake scenarios are split into 90 training events (2,160 rows) and 30 held-out test events (720 rows).

`models/validation_metrics.json` reports held-out synthetic metrics. These measure recovery of the fictional simulator's behaviour, not accuracy in real disasters.

## 4. Re-running the regional model

The included fitted model is sufficient to run the prototype. To refit it from the included CSV:

```powershell
python backend/train_regional_model.py
```

To deliberately regenerate the fictional training data and refit:

```powershell
python backend/train_regional_model.py --generate-demo-data
```

The second command overwrites the selected training CSV and fitted outputs unless alternate paths are provided.
